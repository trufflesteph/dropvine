# Dropvine — Full Codebase Export

This zip contains the **complete current state of your Dropvine project** as it exists in the Emergent build container — the original Dropvine Direct MVP plus the full Dropvine Markets MVP (Phases 1–5).

**Total: 281 files** spanning `app/`, `components/`, `lib/`, `hooks/`, `public/`, `supabase/`, plus all root-level config (`package.json`, `next.config.js`, `tailwind.config.js`, `vercel.json`, etc.).

## What's NOT included (deliberately)

| Excluded | Reason |
|---|---|
| `.env`, `.env.*` | Secrets — never commit. See env var checklist below. |
| `node_modules/` | Regenerated by `yarn install`. |
| `.next/` | Build output — regenerated by `yarn build`. |
| `.git/` | Your repo's git history stays intact. |
| `memory/test_credentials.md` | Local test creds, not for the repo. |
| `test_reports/` | Pytest artifacts from the build agent. |

## Apply to your repo (one of two approaches)

### A. Full replacement (matches your "replace entire repository" intent)

From the **root of your local clone of the repo**:

```bash
# 1. Delete everything EXCEPT .git
find . -mindepth 1 -maxdepth 1 ! -name '.git' -exec rm -rf {} +

# 2. Unzip the export into the repo root
unzip /path/to/dropvine-full-codebase.zip

# 3. Inspect the diff
git status

# 4. Commit + push
git add -A
git commit -m "feat: Dropvine Markets MVP — full codebase push"
git push
```

Windows PowerShell equivalent:
```powershell
Get-ChildItem -Force | Where-Object { $_.Name -ne '.git' } | Remove-Item -Recurse -Force
Expand-Archive -Path \path\to\dropvine-full-codebase.zip -DestinationPath .
git add -A
git commit -m "feat: Dropvine Markets MVP — full codebase push"
git push
```

### B. Overlay (safer — keeps anything in your repo not present here)

```bash
unzip /path/to/dropvine-full-codebase.zip -d /tmp/dropvine-extract
rsync -av --delete-after /tmp/dropvine-extract/  /path/to/your/repo/ \
  --exclude='.git' --exclude='node_modules' --exclude='.next'
cd /path/to/your/repo
git add -A
git commit -m "feat: Dropvine Markets MVP — full codebase push"
git push
```

## Verifying the Vercel build picked up the Markets routes

In the Vercel build log, look for the **Route summary** table near the bottom. You should see:

```
○ /market                3.47 kB
○ /admin                 4.83 kB
○ /admin/dates           ...
ƒ /api/market/admin/login              0 B
ƒ /api/market/admin/vendors/[id]/regenerate-fulfillment-links  0 B
ƒ /api/webhooks/tally-post             0 B
ƒ /api/cron/market-day-push            0 B
… plus ~60 more
```

If those rows are missing, the most common causes are:
1. **Root Directory** in Vercel Settings is set to something other than empty / `./`. Clear it.
2. The push didn't actually include `app/market/` etc. — verify on GitHub: `https://github.com/<owner>/<repo>/tree/main/app/market` should show `page.js` and `layout.js`.
3. A `.vercelignore` file in your repo is excluding directories.
